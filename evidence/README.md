# Archived verification evidence

`archived_verification_status.json` is generated by
`../tools/summarize_archived_runs.py` from the original reports in
`../../IMO/solutions/`. It records, for each package:

- which `litex_verified.json` / `litex_strict.json` files existed;
- how many JSON documents each file contains (some Litex versions emit a
  concatenated stream, e.g. problem 13’s strict report has 92 documents);
- whether every document reports success;
- trace size and `trust` / error mentions.

## What “strict success” means here

- The file is named `litex_strict*.json` or its content is explicitly the
  strict run.
- Every parsed document has `result = "success"` (or `success = true` for the
  older 1.0.x format).
- The trace contains no `trust` mention.
- Ordinary-mode reports contain one expected “imported module is not verified
  in ordinary mode” warning. That warning is why an ordinary report may contain
  one `trust` mention; it is not a proof step using `trust`.

## Regenerate

```bash
python3 tools/summarize_archived_runs.py
```

The script is read-only with respect to the archive.

## Raw reports

The raw JSON reports (several megabytes each for some problems) are intentionally
not duplicated here. They remain in `../../IMO/solutions/problem_*/`. The compact
index is enough to identify which report supports which claim; the raw file can
be opened when a reviewer wants the full trace.
